# 后续开发建议计划（2026-11-22）

> 依据：[文档与实现差异清单](文档与实现差异清单.md) 的核对结果。
> 目标：先用最短路径让**报名业务完整可上线**，再补**榜单模块**，最后做媒体/内容收尾与全量验收。
> 参考体量按 1 名全栈 + 1 名前端估算，仅用于排先后，不作为工期承诺。

## 0. 总体顺序

```
S0 决策与契约（先拍板）
 └─> S1 小程序报名闭环（P0）
      └─> S2 后台运营闭环（P0/P1）
           └─> S3 上线验收（里程碑 M-A：报名业务可上线）
                └─> S4 榜单模块（T28–T31，里程碑 M-B：产品完整）
                     └─> S5 媒体归档/内容联动/赛后清理
                          └─> S6 全量回归与文档收口
```

**为什么这个顺序**：
- 报名主链路后端已完整，小程序与后台只差“最后一公里”，先补齐即可产生业务价值；
- 榜单与报名数据无强依赖，小程序当前是占位页（R10 已定），可在报名上线后迭代；
- 如果业务要求榜单必须随首发上线，把 S4 整体前移到 S3 之前，其余顺序不变。
